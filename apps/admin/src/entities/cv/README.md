# CV

`Global → CV` manages one PDF per website language. The languages come from `SITE_LOCALES` in `@avrash/content-schema/locale`, which the website's routing uses as well, so adding a locale there adds it to this page without other changes. Selecting a file only creates a local preview; **Save CV** uploads and publishes it for the chosen language. Replacing a CV keeps the previous file available until the new upload and metadata write both succeed. Deleting a language's CV unpublishes it first and then removes the file. Hover, keyboard focus, or tap reveals an unavailable label inside the website's button, without changing its size.

- PDF only, up to 4 MiB (leaves room for multipart data within the deployment's request limit).
- Metadata: `cv.json`, `{ "files": { "<locale>": CvDocument } }`, validated by `CvContentSchema`. A file saved before per-language CVs (one document, or `null`) is read as the default language's CV.
- Which CV a visitor gets is decided by `resolveCv`: the CV in their language, otherwise the default language's, otherwise any uploaded one. The admin page shows that fallback for every language without its own PDF.
- Filesystem: metadata and `cv/uploads/<uuid>.pdf` live under `contentDataDir()`. Web reads this directory at request time, so changing a CV does not require rebuilding.
- R2: `content/cv.json` plus `cv/uploads/<uuid>.pdf`, using the existing storage credentials. Every upload gets a new UUID. CV metadata is written with `no-cache`; page rendering caches it for 30 seconds with the `cv` tag and the existing `WEB_REVALIDATE_URL` / `REVALIDATE_SECRET` invalidation. Downloads check current metadata independently and share simultaneous checks.
- Public downloads use the page language in `/api/cv/<locale>` and resolve any fallback at download time. Browser caching uses `ETag` validation: unchanged versions return 304; replacements and newly uploaded languages return the current PDF. The client also retains up to three PDF blobs and explicitly validates their versions, including when native HTTP caching is unavailable. Each server instance retains at most three validated PDF files and shares concurrent reads of a version. The header validates the response before saving, blocks overlapping downloads, and allows another download one second after completion. Failures show a localized retry state instead of saving an error page. The unavailable control remains visible when no CV exists. `cv_download` is emitted after a valid response and carries the actually served language as its `entityId`.
- Admin's authenticated `/api/cv?locale=<locale>` handles preview and deletion, and `POST /api/cv` takes the language as a form field. Preview URLs include `v=<document UUID>` and allow private, immutable browser caching; unversioned downloads remain uncached. An obsolete version returns 404 instead of caching a replacement under the old URL. Uploads accept only site locales. Mutations check the request origin as well as the admin session.
- PDF.js loads only when a preview is needed. The page retains visited languages' documents, workers and canvases, so switching back preserves the PDF page without another request or render at the same size. Unvisited languages are not loaded. Each preview renders one page at a time and caps canvas resolution. Replacing or deleting a CV releases its old preview; leaving the page releases all previews. Draft blob URLs are revoked when replaced or closed. Versioned PDF.js assets are served locally; no third-party PDF service receives the file.

Tests: `cv.test.ts` in content-schema, `cvRepository.test.ts`, admin and web `api/cv` route tests, `e2e/tests/admin/cv.spec.ts`, and the CV case in `e2e/tests/web/analytics-signals.spec.ts`. Browser mutations must run against the E2E server's isolated `ADMIN_CONTENT_DIR`, not real content.
